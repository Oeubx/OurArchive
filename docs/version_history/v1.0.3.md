## 2. Release Scope & Summary of Changes

### Added

- **Personal Fanwork Archive & Granular Visibility Controls (`OA-M2-F6`)**:
  - Contributors can now curate an individual **Personal Archive (Private Vault)** alongside public community indexing.
  - Added an upload-time checkbox in `UploadModal` allowing contributors to designate submissions as Personal Archive only (`is_hidden: true`).
  - Built `PATCH /api/contribute/visibility` allowing contributors to toggle works between `Personal Archive 🔒` and `Public 🌐` at any time with confirmation dialog validation.

- **Immediate Pre-Approval Reading & Reader Owner Bypass (`OA-M2-F4`, `OA-M2-F6`)**:
  - Contributors can stream and read their submitted works immediately in Reader mode (`/reader/[id]`), even while in `verification_status = 'under_verification'` ("In Queue") or stored privately in their Personal Archive.
  - The reader route verifies viewer ownership (`uploader_user_id === user.id`) or administrator privileges before streaming hidden works, while external readers receive a private personal archive notice (`HTTP 403`).

- **Contributor Portal Search-Grade Multi-Filtering & 5/10/15 Pagination (`OA-M2-F6`)**:
  - Enhanced `ContributorTable` on `/contribute` with live keyword search, visibility filter (`All` | `Public` | `Personal Archive`), format filter (`Folders` | `Files`), and verification status pills.
  - Added configurable page size selector supporting **5, 10, or 15** rows per page with responsive pagination and row count tracking.

- **Role-Based Link Masking for Verifiers on Private Personal Works (`OA-M2-F5`, `OA-M3-F6`)**:
  - If a contributor toggles a work to private/personal, the Google Drive link is **strictly masked** for Verifiers in reveal endpoints (`/api/links/reveal`), while remaining accessible in unmasked form to Administrators.

- **Homepage Hero & About Section Personal Archive Detailing (`OA-M2-F5`)**:
  - Updated the `/home` hero container and embedded `AboutContent` to introduce the Personal Reading Vault capability alongside community library searching.

- **In-Memory Ephemeral Stream Child Metadata Scanning (`OA-M2-F2`)**:
  - Built `extractFileMetadataFromDrive` in `metadata-extractor.ts` to ephemerally stream first-page buffers and parse cover metadata in-memory without local storage.
  - Enhanced `/api/links/submit` to batch-scan member documents inside folder collections in chunks of 5, indexing real titles, authors, fandoms, ratings, word counts, and tags for every child work.
  - Added cover author detection heuristics (`by <author>`, `Author:`, `Creator:`) in `metadata-parser.ts` with unit test suite.

- **Upload Modal Folder Details Adaptation & Limits Box (`OA-M2-F5`)**:
  - Dynamically updates upload labels when a folder grouping is toggled: *"Collection / Folder Title"*, *"Curator / Primary Author"*, and *"Primary Fandom(s)"*.
  - Added an informative callout box documenting folderization depth bounds (up to 4 levels), subfolder scan limits (30 folders), and file limits (100 documents maximum).
  - Added scanning wait notice during deep folder inspections: *"This may take a while as we verify the metadata and unpack the files inside this folder..."*.

- **Folder vs. File Search Filtering, Inline Loading & Idle Auto-Load (`OA-M2-F5`)**:
  - Added `entryType` filter parameter (`"all" | "folder" | "file"`) to `/api/search` and `SearchSection`.
  - Added quick format filter pills: `[All Formats]`, `[📁 Folders Only]`, and `[📄 Files Only]`.
  - Added an animated inline loading indicator inside the search input bar.
  - Added a 2.5-second idle debounce timer that automatically fires `onSearch()` when the user pauses after modifying search criteria.

- **Inaccessible Fanwork Fallback & Community Broken Link Reporting (`OA-M3-F5`)**:
  - Replaced the plain error box in `ReaderPage` with a structured diagnostic card when Google Drive returns 404 (file deleted/trashed) or 403 (access restricted).
  - Built `ReportBrokenLinkModal` allowing community readers to report broken or inaccessible links without requiring copyright ownership proof.
  - Allowed `role = 'community'` takedown reports to be logged with an automatic review window in `/api/takedown`.

- **Idempotent Collection Re-sync (`OA-M2-F5`)**:
  - Enhanced `/api/links/submit` to support re-submitting existing folder links without unique constraint failures.
  - Automatically indexes newly added documents inside the folder hierarchy while skipping already-indexed files.

- **Contributor Role Standardization & SQL Migration (`OA-M1-F2`)**:
  - Created `supabase/migrations/20261116_000011_contributor_role_default.sql` setting `role DEFAULT 'contributor'` on `user_profiles` and in `handle_new_user()`.
  - Migrated legacy `'user'` rows to `'contributor'`.

- **Instant User Role Management with Confirmation Validation (`OA-M1-F2`, `OA-M3-F3`)**:
  - Implemented `/api/admin/users/role` endpoint for listing user profiles and updating roles with an immutable audit log.
  - Added User Directory tab in `VerifierRequestsModal` allowing administrators to adjust roles (`contributor` ↔ `verifier` ↔ `admin`).
  - Added a confirmation/cancellation validation modal detailing the exact permissions granted or revoked before role updates are executed.

- **Active vs. History Takedown Desk Tabs (`OA-M3-F2`)**:
  - Split `AdminTakedownContainer` into Active Requests and Resolved / History tabs, isolating resolved items (such as `PURGED` records) from the active triage inbox.

### Changed

- **Admin Dashboard KPI Reordering (`OA-M3-F2`)**:
  - Reordered summary cards to begin with **Total Submissions**, followed by **Approved Works**, **Under Verification**, and **Verifier Applications**.

### Removed

- **Masked Link Section in Admin Desk (`OA-M3-F2`)**:
  - Removed Masked Link row from mobile triage cards and Masked Link column from desktop tables in `AdminDashboardClient`.
