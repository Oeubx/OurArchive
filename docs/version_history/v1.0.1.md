## 3. Database Migrations Required (`v1.0.1`)

**No mandatory database migrations are required for `v1.0.1`.**  
The new adult content features are fully functional out-of-the-box:
- Registration age verification is natively stored by Supabase Auth inside `auth.users.raw_user_meta_data->>'is_adult'`.
- Client-side SafeSearch filtering and reader interstitial confirmations are persisted locally via `localStorage.getItem("ourarchive_nsfw_consent")`.

### Optional Supabase SQL Enhancement (Schema Mirroring)

If administrators wish to mirror the `is_adult` flag directly onto the public `user_profiles` relational table for direct SQL reporting or future server-side RLS enforcement, the following optional migration can be executed in the Supabase SQL Editor:

```sql
-- 1. Add optional is_adult column to user_profiles table
ALTER TABLE public.user_profiles
ADD COLUMN IF NOT EXISTS is_adult BOOLEAN NOT NULL DEFAULT FALSE;

-- 2. Update the auto-provisioning trigger to mirror is_adult from raw_user_meta_data
CREATE OR REPLACE FUNCTION public.handle_new_user()
RETURNS TRIGGER AS $$
BEGIN
    INSERT INTO public.user_profiles (id, display_name, role, is_adult)
    VALUES (
        NEW.id,
        COALESCE(
            NEW.raw_user_meta_data->>'full_name',
            NEW.raw_user_meta_data->>'name',
            NEW.raw_user_meta_data->>'user_name',
            split_part(NEW.email, '@', 1),
            'Anonymous Archivist'
        ),
        COALESCE(NEW.raw_app_meta_data->>'role', 'user'),
        COALESCE((NEW.raw_user_meta_data->>'is_adult')::boolean, FALSE)
    )
    ON CONFLICT (id) DO UPDATE
    SET 
        display_name = EXCLUDED.display_name,
        is_adult = EXCLUDED.is_adult;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;
```
